# deye-monitor

Слідкує за гібридним інвертором **Deye** і пише в Telegram тільки важливе:

- 🔌 **світло вимкнули** / 💡 **світло дали** (з тривалістю відключення);
- 🪫 батарея опустилась нижче порогу під час відключення (за замовчуванням 30 % і 15 %);
- ⚠️ інвертор перейшов у стан **Alarm/Fault** і коли помилка зникла;
- 📵 зник зв'язок з інвертором (Wi-Fi/роутер).

Плюс статистика у SQLite, звіти з графіками й команди бота: `/status`, `/week`, `/month`, `/battery`,
`/stats`, `/history`, `/errors`.

## Звіти і статистика

У режимі `cloud` бот щозапуску дотягує з Deye Cloud 5-хвилинну історію (а при першому запуску — до
30 днів назад), тож відключення рахуються точно навіть між запусками GitHub Actions.

- **Щотижневий звіт** (понеділок після 09:00) і **місячний** (1-ше число) з графіком:
  - відключення: кількість, години без світла, найдовше, середнє, порівняння з попереднім періодом,
    години доби, коли світла зазвичай немає;
  - батарея: скільки віддала, цикли (за період і за весь час), оцінка реальної ємності й «здоров'я»
    за глибокими розрядами, на скільки годин вистачить, температури батареї та інвертора,
    попередження, якщо BMS не передає дані;
  - енергія: спожито, взято з мережі, вартість у гривнях (`TARIFF_UAH`), втрати системи,
    нічне базове споживання;
  - якість мережі: діапазон напруги, частка часу нижче 207 В / вище 253 В, частота;
  - аварії Deye за кодами.
- `/week`, `/month` — той самий звіт за останні 7 / 30 днів; `/battery` — батарея й останні розряди.

Офіційний графік відключень (YASNO/ДТЕК) не підключено: їхнє API закрите захистом від ботів.
Замість цього звіт показує години, коли світла найчастіше немає, за твоїми реальними даними.

Карту регістрів перевірено на реальному **SUN-6K-SG05LP1-EU** з батареєю SE-F12-C (значення збігаються із застосунком Deye).
Розраховано на однофазні низьковольтні гібриди **SUN-xK-SG03LP1 / SG04LP1 / SG05LP1** (наприклад SUN-6K-SG05LP1-EU).

## Два режими

| | `local` | `cloud` |
|---|---|---|
| Звідки дані | напряму зі стіка інвертора по Wi-Fi | з Deye Cloud API (туди стік і так шле дані) |
| Де запускати | пристрій **у тій самій квартирі** (Raspberry Pi, старий телефон) | **будь-де**: VPS, хмарний сервер |
| Затримка | ~1 хв | ~5–10 хв (стік оновлює хмару раз на ~5 хв) |
| Що треба | IP і серійник стіка | AppID/AppSecret з developer.deyecloud.com + логін Deye Cloud |
| Аварії | стан інвертора з регістрів | список аварій Deye з описом і порадою «що робити» |

```
local:  Deye ─ Wi-Fi стік ─(порт 8899)─► deye-monitor (вдома) ─► Telegram
cloud:  Deye ─ Wi-Fi стік ─► Deye Cloud ◄─(API)─ deye-monitor (VPS) ─► Telegram
```

Світло вважається вимкненим, коли напруга мережі на вході інвертора < 180 В.
У режимі `cloud`, якщо хмара перестала отримувати дані (у квартирі зникли і світло, і інтернет),
бот напише «немає даних від інвертора» через ~25 хв після останнього оновлення.

> ⚠️ Інвертор бачить тільки **свою фазу**. Якщо в квартирі зникне одна з трьох фаз, а фаза інвертора
> залишиться, бот цього не побачить. Для повних відключень (графіки) це не важливо.

## Що потрібно

1. Пристрій вдома, який працює постійно і **живиться від виходу Deye** (Raspberry Pi, старий ноут, мініПК).
   Роутер теж має бути на Deye, інакше під час відключення зв'язку не буде.
2. IP-адреса Wi-Fi стіка інвертора (список клієнтів у роутері) і його серійник (10 цифр на наклейці стіка).
   Краще закріпити за стіком статичний IP у роутері.
3. Telegram-бот: напиши [@BotFather](https://t.me/BotFather) → `/newbot` → скопіюй токен.

## Запуск

```bash
git clone https://github.com/olddzen/deye-monitor.git && cd deye-monitor
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # заповни DEYE_LOGGER_IP, DEYE_LOGGER_SERIAL, TELEGRAM_BOT_TOKEN
```

**1. Перевір бота без інвертора.** Постав `DEYE_MODE=simulate`, запусти `.venv/bin/python -m deye_monitor`,
напиши боту `/start`. Він відповість твоїм `chat_id`. Впиши його в `TELEGRAM_CHAT_ID` і перезапусти.
У режимі симуляції «світло» перемикається кожні 2 хвилини.

**2. Підключи інвертор:** `DEYE_MODE=local`.

**3. Звір регістри** (один раз):

```bash
.venv/bin/python -m deye_monitor probe
```

Порівняй `grid_voltage`, `soc`, `load_power` з тим, що показує застосунок. Якщо щось не збігається,
адреси регістрів лежать у `deye_monitor/inverter.py`.

**4. Запусти постійно**, одним із двох способів:

```bash
docker compose up -d --build
```

або через systemd на Raspberry Pi: `deploy/deye-monitor.service`.

## Режим cloud (без пристрою вдома)

1. Переконайся, що інвертор видно в застосунку **Deye Cloud** (не Solarman Smart). Якщо його там немає,
   додай станцію в Deye Cloud за серійником стіка.
2. Зайди на [developer.deyecloud.com](https://developer.deyecloud.com) тим самим акаунтом → створи застосунок
   → скопіюй **AppID** і **AppSecret**.
3. У `.env`: `DEYE_MODE=cloud`, `DEYE_CLOUD_APP_ID`, `DEYE_CLOUD_APP_SECRET`, `DEYE_CLOUD_EMAIL`, `DEYE_CLOUD_PASSWORD`.
4. Перевір: `python -m deye_monitor cloud-check` покаже станцію, інвертор і всі точки даних.
   Якщо рядок `Detected grid voltage` порожній, впиши потрібну назву точки в `DEYE_CLOUD_GRID_VOLTAGE_KEY`
   (без неї світло визначається за потоком потужності з мережі, це менш точно).
5. Запусти на сервері: `docker compose up -d --build`.

### Безкоштовно на GitHub Actions (без сервера)

Workflow `.github/workflows/monitor.yml` раз на ~5–15 хв запускає `python -m deye_monitor once`:
одна перевірка + відповіді на команди бота. Історія відключень зберігається в кеші Actions.

1. Репозиторій має бути **публічним**: для публічних репозиторіїв хвилини Actions безкоштовні.
   У коді немає жодних ключів, усе зберігається в Secrets.
2. Settings → Secrets and variables → Actions → додай секрети:
   `DEYE_CLOUD_APP_ID`, `DEYE_CLOUD_APP_SECRET`, `DEYE_CLOUD_EMAIL`, `DEYE_CLOUD_PASSWORD_SHA256`,
   `DEYE_CLOUD_STATION_ID`, `DEYE_CLOUD_DEVICE_SN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
3. Actions → Deye monitor → **Run workflow**, щоб перевірити.

Мінуси: GitHub запускає cron із затримкою, тому сповіщення приходять через 5–20 хв, а бот відповідає
на команди при наступному запуску. Workflow `keepalive.yml` не дає GitHub вимкнути розклад через 60 днів.

### Миттєвий /status і надійний запуск: Cloudflare Worker

Cron GitHub Actions ненадійний (може не запускатись годинами), а бот на Actions відповідає із затримкою.
Тому в `worker/` лежить безкоштовний Cloudflare Worker:

- Telegram webhook → `/status` відповідає за 1–2 с прямо з Deye Cloud (світло, відколи, батарея,
  навантаження, мережа, температури, вік даних);
- `/week`, `/month`, `/battery`, `/history`, `/stats`, `/errors` → запускає workflow з `command`,
  звіт приходить приблизно за хвилину;
- cron кожні 5 хв запускає моніторинг на GitHub (власний розклад GitHub лишається запасним, раз на 15 хв).

Розгортання (`cd worker`): `npx wrangler kv namespace create deye-monitor-kv` (id → `wrangler.toml`),
`npx wrangler deploy`, секрети через `npx wrangler secret put` (список у `wrangler.toml`), де `GITHUB_TOKEN` —
fine-grained токен лише на цей репозиторій з правом **Actions: Read and write**. Далі Telegram `setWebhook` на
`https://<worker>.workers.dev/telegram` з `secret_token` = `TELEGRAM_WEBHOOK_SECRET`.

### Дашборд у Telegram (Mini App)

Кнопка «📊 Дашборд» у меню бота (або `/dashboard`) відкриває сторінку воркера `/app`: стан світла,
кільце заряду, потоки енергії наживо, стрічка «сьогодні», графіки заряду й споживання за 7 днів,
теплова карта «коли немає світла» за 4 тижні, години без світла по днях, історія відключень, батарея,
мережа, аварії. Дані віддає `/api/data` лише після перевірки підпису Telegram (`initData`) і лише
власнику (`TELEGRAM_CHAT_ID`). Меню: `setChatMenuButton` з `web_app.url = https://<worker>/app`.

Щоранку о `MORNING_HOUR` (за замовчуванням 8) бот надсилає підсумок ночі.

### Або на сервері 24/7

Безкоштовний або дешевий сервер, що працює 24/7: Oracle Cloud Always Free, Google Cloud e2-micro (free tier),
або будь-який VPS за ~3–5 €/міс (Hetzner, DigitalOcean). Достатньо найменшого тарифу.
